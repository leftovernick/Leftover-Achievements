# Contributing to LeftoverAchievements

Bug reports, feature suggestions, documentation improvements, and focused pull
requests are welcome. LeftoverAchievements is source-available rather than open
source, so contributions follow the project license and the terms below.

## Before starting

- Open an issue before beginning a large feature, redesign, dependency change, or
  architectural change.
- Keep pull requests focused on one problem.
- Do not include API keys, user databases, logs, personal data, or generated build
  artifacts.
- Use only code, text, audio, and images that you created or have the right to submit.

## Submitting a change

1. Create a GitHub fork solely for preparing the contribution.
2. Create a focused branch and make the change.
3. Add or update tests when behavior changes.
4. Run the relevant test suites.
5. Open a pull request that explains the problem, the solution, and how it was tested.
6. Complete every applicable item in the pull-request checklist.

Pull requests are proposals. The project owner may request changes, edit an accepted
contribution, or decline it for any reason. Only the project owner decides what is
merged and released.

## Contribution license

By submitting a pull request, patch, code sample, documentation change, issue content,
or other material intended for inclusion in LeftoverAchievements, you agree to the
[Contributor License Agreement](CLA.md). Do not submit a contribution if you cannot
agree to those terms.

## Style

- Match the surrounding code and naming conventions.
- Prefer clear, direct code over unnecessary abstraction.
- Write comments about the current behavior or architectural reason, not the history
  of a prompt or implementation attempt.
- Keep user-facing text concise and specific.
- Preserve unrelated work already present in the repository.

## Reporting security problems

Do not open a public issue for an unpatched vulnerability. Follow the private
reporting guidance in [SECURITY.md](SECURITY.md).
